# решения мейнтейнера

решения по новым патчам десктопа (0125–0332, lib_ui), принятые при разборе очереди. номера — текущие номера патчей десктопа ([desktop-numbers.md](desktop-numbers.md)); `A0068` — файл `patches/android/`. планирование — [PATCHLIST.md](PATCHLIST.md), оценки — [portability.md](portability.md).

два уровня:

- **мейнтейнер** — спрошено и отвечено, решение обязательно.
- **по умолчанию** — решил лид при разборе, пока мейнтейнер не ответил; мейнтейнер может переиграть, тогда правится и план, и оценка.

## решения по базе приватности (пачка 11)

| тема | решение |
|---|---|
| режим игнора (0016) | режим (`hide`/`fade`) задаётся на каждого peer в пикере, а не одним глобальным тумблером, как в десктопе. список хранится в `tele_kv` с account в ключе |
| игнор и слова (0016, 0166) | игнор скрывает или гасит сообщения и превью; слова всегда скрывают полностью. свои, сервисные и sponsored-сообщения не трогаем |
| превью в списке чатов | если последнее сообщение скрыто, превью не показывается. подстановка более раннего сообщения, как в десктопе, не перенесена: истории чата нет в синхронном доступе на UI-треде |
| ghost по чатам (0032) | per-chat работают только typing, read и contents-read. онлайн-статус остаётся глобальным, как в десктопе: per-peer онлайн невозможен |
| ghost-schedule (0032/0064) | задержка 12 секунд, как в десктопе. в android нет мастер-тумблера ghost, поэтому признаком ghost-режима считаем включённый `ghost_schedule` вместе с глобальными ghost-переключателями |
| ожидающие сообщения (0227) | локальная копия ghost-scheduled сообщения лежит в чате, а не в списке отложенных; при доставке сервером строка обновляется, второго ряда не появляется |
| last seen (0282) | правило last seen меняется на allow-users, статус читается, исходное правило восстанавливается и переживает перезапуск приложения. пункт — в меню чата, тумблер выключен по умолчанию |
| streamer mode (0160) | приоритет над 0113 (never block screenshots): пока включён streamer mode, `FLAG_SECURE` всегда стоит. заголовок окна и трей — desktop-only |
| поиск | новые privacy-строки получили id 1110–1120: диапазон 1100–1119 из гайда пачки 11 уже занят фичами предыдущих пачек (calcmula, shot) |
| ghost mode | добавлен общий мастер-тумблер «Ghost mode» (выключен), как в десктопе: переключатели online/typing/read/viewed/scheduled работают только пока он включён. per-chat «always ghost» работает и без мастера. состояние видно в счётчиках «always ghost in (N)» / «never ghost in (N)» |
| игнор-лист | только люди, каналы и группы игнорировать нельзя — как в десктопе. кнопка «Ignore messages» в профиле появляется, пока включён тумблер «show the ignore button in the profile» (по умолчанию включён — кнопку просил мейнтейнер) |
| слова | по умолчанию сообщения гаснут, полное скрытие — тумблер «hide the messages completely» (в десктопе наоборот: fade по умолчанию, полное скрытие отдельной опцией) |
| read при ghost | пункт «Read» в меню сообщения помечает сообщение прочитанным локально, без отправки read receipt. появляется только когда включён ghost read |
| пикер исключений (0016, 0032) | пикер игнора и ghost-исключений — стоковый экран пересылки (`DialogsActivity`, `DIALOGS_TYPE_FORWARD` + `selectAlertString`): список чатов с галочками, счётчик получателей и нижняя панель, как при пересылке нескольким людям. в режиме игнора выбираются только люди (как в десктопе), группы и каналы нельзя отметить. свой список чатов с поиском удалён |
| живое превью ghost (0244) | карточка «you / what they see» в разделе ghost, над мастер-тумблером: заголовки — системные сообщения (цвета `key_chat_serviceBackground`/`key_chat_serviceText`), строки — плашки профиля из заголовка диалога (настоящая аватарка, имя, статус) с бейджем stealth на аватарке, «On my way…» — поле ввода, «See you tomorrow?» — пузыри (наш с одной галочкой = не прочитано), «Their story» — кружок истории с буквенной аватаркой и текстом справа, «12 views» — иконка stealth. клик по строке переключает соответствующий тумблер, пока ghost включён, иначе карточка приглушена. строка сторис показывает «watch stories invisibly» и не переключается — отдельного «не отмечать сторис просмотренными» в android нет |
| иконка stealth | взята стоковая `R.drawable.msg_stories_stealth2` — та, что telegram использует для premium-пункта «Hide My View» в историях (`PeerStoriesView`). свой вектор с перечёркнутым глазом удалён |
| краш в профиле | `TeleHooks.onPrivacyRulesChanged` отправлял `NotificationCenter.messagesDidLoad` без аргументов — `ChatActivity` читал `args[10]` и падал с AIOOBE. теперь чаты перебиндовывают ячейки по счётчику ревизии (`TeleHooks.uiRevision`), а список чатов обновляется через `dialogsNeedReload` |
| peek last seen | если правила приватности ещё не в кэше, tele грузит их с сервера и ждёт до 10 секунд, вместо сообщения «the privacy rules are not loaded yet» |
| регистр строк форка | строки форка (экраны, пункты, диалоги, тосты, поиск) с заглавной буквы — как в android-телеграме; в десктопе всё в нижнем регистре. «tele» всегда строчными, включая «tele server URL» и «New in tele». технические строки (sql, регулярки, ключи, коды ошибок) и статусы вида «online»/«recently» не менялись |
| телефон в streamer mode | в режиме стримера номер не показывается нигде, где он мог бы служить именем: в заголовке чата (для не-контакта телеграм подставляет номер вместо имени), в `UserObject.getUserName` (fallback на номер → «Unknown»), в своём профиле (строка «Mobile»). в десктопе тот же приём — `Tele::StreamerPhone()` отдаёт пустую строку |
| переход из поиска | результат поиска открывает страницу tele и проматывает её к нужному тумблеру с подсветкой. используется стоковый механизм: `SearchResult.rowName` + `AndroidUtilities.scrollToFragmentRow`, который ищет в фрагменте поле `listView` и поле с номером строки — форк отдаёт туда поле `teleSearchRow` |
| link rewrite | цель при «Pick a random target» выбирается случайно на каждую перезапись (раньше — по хешу ссылки, и одна и та же ссылка всегда превращалась в один и тот же домен). уведомление — телеграмный баултин с «домен_до -> домен_после», а не системный тоаст |

## пачка 25: инспектор, консоль и диагностика

1. источник TL-схемы — собственные сгенерированные классы этой сборки (`TLRPC.java` и `tgnet/tl/*.java`, layer 232). `ci/tl_index.py` делает из них компактный индекс (`res/raw/tele_tl_index.json`, 3064 класса, 622 метода) с id конструктора, родителем и признаком метода; индекс детерминирован и проверяется глазами на каждом апдейте layer. внешняя схема (desktop `api.tl`, schema.jppgr.am) рантаймом не используется — schema.jppgr.am остаётся только ссылкой по тапу.
2. консоль не пишет собственный сериализатор: она инстанцирует настоящий сгенерированный класс запроса через reflection, поля заполняются по типам, отправка идёт штатным `ConnectionsManager.sendRequest`, ответ десериализует сам класс. так невозможен рассинхрон слоя и отсутствует риск hand-written TL.
3. UI инспектора и консоли — native (`RecyclerListView`, `EditText`), а не webview с HTML/CSS/JS десктопа: экраны доступнее для TalkBack, не тянут второй рантайм и не требуют JS-bridge. это же снимает половину требований плана про allowlist `@JavascriptInterface`.
4. захват — на Java-границе TL (`sendRequestInternal` до сериализации и в callback после нативного ответа, `onUnparsedMessageReceived` для апдейтов). encrypted wire, retries и ACK внутри tgnet не видны; в UI это честно называется Java TL inspector, JNI-хук не делался.
5. хранение — кольцо 300 записей на аккаунт, 4 КБ на каждую сторону, private files, атомарная замена, запись дебаунсится секундой; `networkType`, auth/secret/key/hash/token/phone редактируются, `user_id`/`chat_id`/`channel_id` — нет. лог аккаунта удаляется при выходе из него, кнопка «Clear the log» показывает размер.
6. опасные методы: список 34 методов десктопа плюс шаблоны `.delete`, `leave` и `*TTL` кроме `get`. классификатор работает на Java-стороне (JS-метаданным не доверяем), диалог нельзя отключить тумблером, для оплат добавляется пароль пачки 23 (`StarsLock` по действию), для аккаунтных — `StarsLock.confirm`.
7. гейт для отчётов 0202/0203 — существующий `Send crash reports` + непустой server url; новый тумблер загрузки не вводился, чтобы не раздваивать согласие. отправка по-прежнему только после нажатия пользователя.
8. freeze watchdog: heartbeat с UI-потока, отдельный daemon-читатель, порог 15 с по `elapsedRealtime`, один маркер на эпизод (`tele_freeze.txt`), на следующем старте маркер превращается в диагностический отчёт с `Tele-Note: freeze N s` и удаляется после ответа пользователя.
9. отчёты без дампа: причина берётся из `ApplicationExitInfo` (API 30+), каждая смерть обрабатывается один раз (`diag_last_exit`), в отчёт попадают только `Tele-Note`, описание выхода и цифры памяти.
10. инструменты лежат на странице `tele · Debug`, как в десктопе; отдельной страницы `tele · Diagnostics` нет, а прежняя заглушка Debug («опций десктопа ещё нет») удалена.
11. включение `Capture MTProto` показывает предупреждение десктопа «Do you want to enable DEBUG logs? All network events will be logged.»; отмена оставляет тумблер выключенным. импорт бэкапа тумблер не переспрашивает — это явное действие пользователя.
12. у консоли нет отдельного тумблера: вход со страницы Debug сразу открывает список методов. история последних 20 запросов по аккаунту ведётся всегда и только в памяти (на десктопе опции истории нет; на Android она нужна, чтобы вернуться к недавнему запросу, но raw-ввод не хранится дольше сессии).
13. модель записи лога — как в десктопе: отдельные строки `send` (запрос), `recv` (ответ или ошибка) и `other` (апдейты), у каждой свой JSON и размер; пара send/recv связывается токеном только для длительности. JSON ограничен 16 КБ на запись и всегда остаётся валидным: при достижении лимита недописанные поля отбрасываются, а не обрезается строка. детали открываются отдельным экраном с деревом, сворачиванием, подсветкой и копированием.
14. в JSON каждой записи первой строкой идёт `_` с именем конструктора — как в десктопе. конверта wire-сообщения (`msg_id`, `seq_no`, `bytes`, `body`) у нас нет: он живёт внутри tgnet, Java видит уже разобранный объект; auth/secret/key/hash/token/phone по-прежнему редактируются, поэтому `access_hash` в записи выглядит иначе, чем на десктопе. это осознанные отличия, а не рассинхрон схемы.
15. обязательность полей в консоли берётся не из внешней схемы, а из самой сборки: `ci/tl_index.py` вытаскивает из сгенерированных `readParams`/`serializeToStream` карту «поле → бит flags» (`"o"` в индексе), и всё, чего в ней нет, считается обязательным. поэтому `account.acceptAuthorization` в этой сборке требует и `credentials`, хотя десктопная схема помечает его необязательным: Android-сериализатор пишет поле безусловно.
16. панель «?» консоли описывает не текстовый синтаксис десктопа (у нас нет режимов Text/JSON — только типизированная форма), а то, что принимают поля: числа, строки, флаги, векторы, байты, вложенные конструкторы и обязательность. тексты секций и порядок повторяют десктопный экран Syntax.

## пачка 26: деньги и ключи

1. движок берём из `gettele/money` как патч поверх пришпиленного `dkaraush/wallet-engine@5c65e47`, а не готовые бинарники: `jni/gram-wallet/engine-private-key.patch` (порт 1804 строки, два конфликта решены под нашу ревизию) накладывается CI-шагом на сабмодуль, затем `build_wallet_engine.sh` пересобирает движок под 4 ABI и перегенерирует C++-биндинги. в git не коммитятся ни новые `.a`, ни новые заголовки: их делает сборка. локально — тот же скрипт, иначе JNI не соберётся.
2. форс-кошелёк сделан методом `AppGlobalConfig.walletAvailable()` (локальный флаг `force_wallet` или серверное значение) и заменой всех чтений `config.walletAvailable.get()`; рестарт не нужен, в отличие от десктопа.
3. приватный ключ — это «секрет» в том же `SecretPhrase` (байтовый контейнер), поэтому хранилище, шифрование и импорт не менялись: движок сам распознаёт ключ, `detect_private_key` отличает его от слов. ключ не участвует в облачном бэкапе, экран так и говорит.
4. ротация без бэкапа идёт отдельным путём `prepareKeyRotation`/`sendKeyRotation`, и срок жизни transfer поднят до 10 минут: сток даёт 2 минуты, а пользователь за это время должен записать и проверить 12 слов, иначе `wallet.sendTransfer` возвращает `WALLET_TRANSFER_SEND_FAILED`: transfer тот же, но серверный `disableBackup` не вызывается, а новая фраза пишется в локальное хранилище **после** успешной отправки (иначе неудачный transfer оставлял бы устройство с новым ключом при старом ключе на цепи). причина неудачи отправки показывается буллетином, а не только «Failed transfer».
5. `0307` на Android не портировался: BoC смены ключа строит Rust-движок, десктопный парсер `gram_boc.cpp` в Android не участвует; квота `emulateRotateKey` покрыта тестами движка.
6. `recover_wallet_secret` (адрес + 12 слов ротации) есть в движке и биндингах, но UI-входа пока нет: импорт принимает ключ и ключ + 12 слов. это осознанно оставлено на следующий заход.
7. вставка нескольких слов в поле секретной фразы раскидывается по ячейкам: перехват контекстного меню `paste` и признак «вставилось больше одного символа за раз» в `TextWatcher` (печать по символу не трогается); раскладка повторяет штатную кнопку Paste.

## пачка 28: скриптинг

1. движок — QuickJS-ng 0.17 из десктопного патча, собранный CMake как статическая библиотека под все ABI; JS-файлы `runtime.js`, `web.js` и TypeScript-stripper `strip.js` перенесены из десктопа без изменений, `tele_script_*` C++ не переносился: хост написан на Kotlin/JNI, а `tg.call` собирает настоящий сгенерированный TL-класс через reflection, как консоль пачки 25, и отправляет его штатным `ConnectionsManager`.
2. один скрипт — один поток, один isolate и один generation; JS никогда не выполняется на UI/stage queue, а host-вызовы блокируют только поток скрипта. Остановка ставит cancellation, снимает таймеры, меню и декорации и уничтожает isolate; после остановки callback'и отбрасываются.
3. папка — `getExternalFilesDir()/tele/scripts` по умолчанию; «Change the folder» выбирает любой каталог через `ACTION_OPEN_DOCUMENT_TREE`, сохраняет persistable-разрешение глобально и останавливает все скрипты перед загрузкой нового каталога; «Use the default folder» возвращает app-папку. «Open the scripts folder» сначала пробует file manager (FileProvider/tree), а если его нет — показывает встроенный список файлов и путь. «Rescan» вызывает тот же скан, что и открытие страницы, и hot-reload по изменению source. Импорт файла идёт через SAF, импорт по ссылке — OkHttp с http(s), лимитом 5 МБ, 30 с и проверкой каждого редиректа; имя берётся из конца URL, ссылка запоминается как update link, скрипт остаётся выключенным. `tele.d.ts` и `tsconfig.json` пишутся с точными именами (MIME `application/octet-stream`, иначе SAF добавляет `.txt`); `tsconfig.json` пользователя не перезаписывается.
4. grants хранятся per account и script, парсер один (`ScriptGrants`), неизвестный grant не запускает скрипт; consent показывает каждый grant простым текстом и отдельно предупреждает об опасных. Выключение скрипта забывает approvals, storage остаётся.
5. `display(messages)`: `tg.decorateMessage` и `tg.decorateMessages` работают через `ScriptDisplay`; декорация применяется в `MessageObject.generateLayout` до построения layout, поэтому меняет только локальный вид и не пишет на сервер. `display(peers)` и локальные сообщения пока не имеют UI: хост возвращает `unsupported`, а не притворяется, что сработало.
6. веб-платформа: `fetch` идёт через OkHttp с одним общим клиентом, per-host grant, ручными редиректами (каждый хост проверяется), лимитом 16 МБ и без cookies/заголовков Telegram. `web.js` даёт URL, URLSearchParams, EventTarget, AbortController и structuredClone; WebSocket, `crypto.subtle` и Intl в этой пачке не включены и честно возвращают `unsupported`/отсутствуют.
7. TL-мост по умолчанию блокирует `auth.*`, удаление аккаунта, пароль и login-token; 64-битные id и access_hash ходят через BigInt-кодек, а неизвестные конструкторы дают `TeleError`, не падение. `onUpdate` и `onNewMessage`/`onMessageEdited`/`onMessageDeleted` получают immutable JSON-снимок после штатной обработки, поэтому seq/pts не меняются.
8. меню: message-menu items регистрируются в `ScriptMenu`, показываются на main thread и снимаются при остановке; icon — только фиксированный набор стоковых drawable, неизвестное имя оставляет пункт без иконки (0329). Остальные поверхности десктопа (виджеты, панели, Monaco, webview-панели, звонки, истории, подарки, inline, media viewer, `unsafe.exec`, RPC/update interceptors) не портированы в этой итерации и возвращают `unsupported`.
9. проверено на эмуляторе: скрипт из папки запускается, `tg.call(help.getConfig)` отвечает, `tg.sendMessage` в Saved Messages работает, `display(messages)` после consent заменяет текст сообщения, повторный запуск после изменения source перезапускает runtime, master OFF не создаёт ни потока, ни isolate; смена папки на SAF-каталог пишет `tele.d.ts`/`tsconfig.json` точными именами и возвращается к app-папке; импорт по ссылке (`cdn.jsdelivr.net/.../dayjs.min.js`) скачивает файл, а `tg://tele/script?url=…` открывает диалог с заполненным URL.
